# SoundShelf v0.1.0 — pre-release notes

Initial Linux MVP candidate, **not an officially published release**. No Git tag, GitHub Release or upload has been created by Codex. The user reports successful acceptance of the fixed installed Debian application. The user approved the original icon replacement and MIT licensing of their own screenshot image rights on 2026-11-04. Those blockers are resolved; final package installation/launcher acceptance and publication approval remain pending; see the [release checklist](../RELEASE_CHECKLIST.md) and [license review](../THIRD_PARTY_LICENSE_REVIEW.md).

## Initial MVP overview

SoundShelf is a local-first Linux desktop audio asset manager built with Tauri 2, Rust, React, TypeScript, Vite and SQLite. Milestones 1–4 implement:

- Trusted native directory selection and recursive, read-only WAV/MP3/OGG discovery, with progress and partial/unavailable states.
- Filename, relative-path and tag search, deterministic pagination, favorites and combined tag filters.
- One player with play, pause, resume, stop, seek and recoverable errors.
- Tag creation/renaming/deletion and asset assignment, with SQLite metadata independent of original audio files.
- Persistent results/tags/favorites; restart requires native-picker reauthorization for scans/playback.
- Keyboard controls, visible focus, loading/error feedback and light/dark styling.

The pause → seek → resume → pause regression was fixed by separating play intent from readiness and rejecting stale promise/event results. The earlier `invalid duration 0` assertion was a separate test-harness issue. The [investigation](../PLAYBACK_DURATION_INVESTIGATION.md) records both.

## Supported/tested environment

The package is **amd64/x86_64**, built on Zorin OS 18.1 (Ubuntu noble base), Linux 7.0.0-42-generic, glibc 2.39, GTK 3.24.41, WebKitGTK 2.52.6, libsoup 3.4.4 and GStreamer tools 1.24.2. Build tools tested: Rust/Cargo 1.99.1, Node 24.12.0, npm 11.21.1, Tauri CLI 2.12.4. Locked Linux dependencies declare minimum Rust versions up to 1.90; that minimum toolchain itself was not tested.

The executable requires **GLIBC_2.39** and Linux `openat2`, with no insecure compatibility fallback. Windows, macOS, older glibc systems, other architectures and other distributions have not been accepted. This is not a compatibility matrix; the latest user report does not include its own runtime-version log.

Declared Debian dependencies: `libc6 (>= 2.39)`, `libgcc-s1`, `libsoup-3.0-0`, `gstreamer1.0-plugins-base`, `gstreamer1.0-plugins-good`, `gstreamer1.0-libav`, `libwebkit2gtk-4.1-0`, `libgtk-3-0`. A graphical desktop and suitable codecs are required. SQLite is compiled in. Running the installed application requires no Node, Rust, Vite, database server, account or external service.

## Installation and removal

Close all SoundShelf instances. From the reviewed candidate directory, use the graphical package installer or an authenticated package-manager session:

```sh
pkexec apt install --reinstall "$(realpath soundshelf_0.1.0_amd64.deb)"
soundshelf
```

`--reinstall` handles replacement of the same version, 0.1.0. Resolve dependencies rather than forcing installation failures. Codex did not install or remove packages. To uninstall:

```sh
pkexec apt remove soundshelf
```

The package has no user-data cleanup script. Metadata remains at `$XDG_DATA_HOME/dev.soundshelf.app/soundshelf.sqlite3`, normally `$HOME/.local/share/dev.soundshelf.app/soundshelf.sqlite3` when XDG_DATA_HOME is unset. Do not delete that directory for reinstall testing. The user reports data-preserving reinstallation; an explicit uninstall/remove test is not separately recorded.

Use [isolated data](../RELEASE_CHECKLIST.md#manual-packaged-linux-acceptance-reference) for follow-up checks. After restart, stored results remain searchable/editable but scans/playback require native picker reselection.

## Privacy and security scope

There are no accounts, telemetry, cloud services or required external API keys. Media stays local. Original bytes, embedded tags, filenames and intentional timestamps are not written; OS reads may update atime. Only SoundShelf metadata is written to its own SQLite index.

Native picker selection alone authorizes filesystem access. Stored paths grant no authority after restart. Scans/playback resolve beneath retained directory handles using `openat2`, rejecting traversal, symlinks and nested mount crossings. Main-window capabilities grant only explicit application commands, without broad filesystem/shell/asset scope. Identifier `dev.soundshelf.app` and the database schema/location are unchanged.

Media uses an ephemeral `127.0.0.1` listener with opaque expiring tokens, host/origin checks, revalidation and bounded range streaming. The internal `soundshelf-audio://` locator is translated to that HTTP route; no old custom media scheme or unrestricted file URL fallback is registered. Another local process possessing an active bearer token can read that authorized stream; buffered audio cannot be withdrawn.

Static inspection and regressions support these statements within their scope; this is not an independent security audit or proof that arbitrary secrets/vulnerabilities cannot exist. License/source-compliance materials are intentional package documentation. Unused starter SVGs were removed; the default application icon has been replaced by original SoundShelf artwork.

## Known MVP limits

- Codec availability controls playback; corrupt/empty candidates can be indexed but fail decoding recoverably.
- Identity follows relative paths: replacement retains annotations; moving creates another record. Unavailable records are retained without automatic reassociation/pruning.
- Partial/failed scans preserve metadata. Limits are 100,000 entries, 10,000 candidates, depth 64 and a cooperative 30-second deadline, which cannot interrupt blocked filesystem calls.
- No watcher, atomic snapshot, undo or multi-instance index coordination. Tags are global; search/filter UI selections are not persisted.
- Search uses literal SQLite LIKE, without full Unicode normalization/case folding or measured large-library performance guarantees. Multiple selected tags require all selected tags.
- Playback tokens expire after one hour, with 32 grants retained. Multipart ranges, conditional validators and an automatic updater are not implemented.
