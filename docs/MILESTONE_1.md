# Discovery implementation and verification

Milestones 1B–1E have an implementation with automated coverage. Final Milestone 1 acceptance still requires the manual native Linux checks below. This document does not certify the scanner as security-complete or replace those checks. SQLite, playback, tags, favorites, and Milestone 2 have not been implemented.

## Implementation

- `commands.rs`: main-window-only Tauri handlers; asynchronous native GTK directory selection; worker dispatch; scan status and result queries.
- `library.rs`: opaque random IDs, session root authorization, overlap rejection, and library state. Only the Rust picker handler can authorize paths in the application; no path-authorization command is registered.
- `secure_fs.rs`: retained root descriptors, identity validation, and Linux `openat2` access. Root selection rejects symlinks, checks canonical identity against the opened directory, and requires reselection after observed removal, replacement, or inaccessibility. Discovery resolves every full relative path from the authorized root with `BENEATH`, `NO_SYMLINKS`, and `NO_XDEV`. There is no canonicalize-and-open fallback. The helper rejects write flags.
- `scan.rs`: recursive worker discovery, case-insensitive WAV/MP3/OGG candidates, native path storage, stable per-path IDs within the session, progress, bounded warnings, partial results, and a per-library running guard. Files are opened read-only and never decoded or changed. Nonregular files are excluded; read opens are nonblocking to handle replacement with a FIFO safely.
- `contracts.rs`, `src/lib/types.ts`, `src/lib/contracts.ts`, and the shared IPC fixture: explicit Rust serialization, TypeScript declarations, and checked runtime responses. Display paths are never used to reconstruct native paths.
- `src/lib/library-controller.ts` and `App.tsx`: selection, explicit scan/refresh, polling, list rendering, accessible states, and generation checks for stale responses. Canceling a picker preserves the view and does not stop an existing scan.
- Tauri command permissions are generated from `build.rs` and granted only to the main window. The capability contains four application commands and no general filesystem, shell, opener, or dialog-plugin permissions. Production CSP permits bundled content and IPC; local Vite allowances are confined to `devCsp`.

The sample command and starter greeting were removed after the replacement workflow passed automated checks. The unused opener plugin was removed from Rust and npm dependencies.

## Dependencies

Direct Rust dependencies added: `rustix` with its filesystem feature for safe Linux syscall wrappers; `gtk` for the native chooser already used by Tauri on Linux; and `getrandom` for opaque session identifiers. `sha2` is a test-only dependency for file-integrity checks. No frontend dependency or new native library requirement was added. Dependency resolution used the existing local cache offline.

## Test coverage

Rust coverage includes trusted-selection cancellation outcomes, invalid authorization, overlapping roots and prefix collisions, nested and mixed-case extensions, repeat scans, non-UTF-8 filenames, static symlinks, controlled file/directory symlink replacements, directories moved outside after opening, root revocation before publishing results, real unprivileged permission failures, disappearing entries, bounded warnings and depth, concurrent-scan rejection, progress, and a FIFO replacement. Integrity tests compare SHA-256 hashes, directory contents, modes, and modification times before and after discovery.

Integration tests compile the same private core modules into a separate test crate rather than publishing a production path-authorization API. Race hooks execute at explicit access boundaries, avoiding timing-dependent attack loops. All filesystem fixtures are disposable synthetic trees under the temporary directory. No personal audio directory is scanned by tests.

The same JSON fixtures are compared against actual Rust serialization and parsed by the TypeScript boundary. Frontend workflow tests cover cancellation, background polling, partial/empty results, revoked authorization, busy scans, mismatched scan IDs, late results from old libraries, and late scan-start/picker responses. These are native-API simulations, not an end-to-end WebView/picker test.

Environment inspected for verification: Zorin OS 18.1, Linux 7.0.0-38-generic, GTK 3.24.41, WebKitGTK 2.52.6, Rust 1.99.1, and Node.js 24.12.0. Permission-denied tests run as UID 1000 and assert that the OS actually denies access; they do not silently skip under root. An older kernel or syscall-restricting sandbox has not been exercised; secure-open failures return errors without falling back.

The Tauri executable build (`--debug --no-bundle -- --offline`) succeeded with bundled frontend assets. A bounded startup smoke attempt in the execution sandbox failed before the UI opened because Tauri's GTK backend could not initialize. Native picker interaction, actual WebView IPC/CSP behavior, and GUI responsiveness remain unverified here. Run the checks below in a desktop session with working GTK display access; no filesystem security settings were relaxed to work around the startup failure.

## Limits and security scope

- Authorization and results are in memory only. At most 16 active roots are retained per session; restart clears authorization. Overlapping roots are rejected. Existing roots can be reselected.
- A scan checks at most 100,000 entries and retains at most 10,000 candidates and 100 detailed warnings. Directory depth is limited to 64. The 30-second deadline is checked cooperatively between operations; it cannot interrupt a filesystem syscall blocked on a slow or remote-mounted filesystem. Reaching limits produces partial results.
- Symlinks, including links within the selected tree, are skipped. Nested mount points are rejected by `NO_XDEV` and may produce partial results. A selected root may itself reside on a mounted filesystem.
- Every access resolves beneath the retained root, and root identity is rechecked during commands, traversal, and before publication. This is not an atomic filesystem snapshot or a filesystem watcher. Changes occurring entirely between checks may not be detected; a file may disappear immediately after a successful scan. Already-open descriptors refer to their original objects. Concurrent modification by another process is outside SoundShelf's control.
- Hard links inside a selected tree are regular files; path containment does not establish a file's provenance. The implementation trusts the Linux kernel's resolution guarantees and the host filesystem; automated race tests are not a general security audit.
- Current availability values describe readable and inaccessible candidates at scan time. Duration is `null`, and extensions do not prove valid or playable audio. Missing entries disappear on a successful rescan in this in-memory milestone; persistent missing-record reconciliation belongs to Milestone 2. Non-UTF-8 display names may look identical, but native paths and IDs remain distinct.
- Switching directories does not cancel an already-running worker for another library. Its results cannot replace the current view. A worker terminates when discovery finishes, encounters a fatal error, or reaches a cooperative limit.
- Normal filesystem reads may update OS access timestamps. SoundShelf does not intentionally set timestamps or modify original bytes, modes, names, embedded metadata, or directory contents.

## Manual Linux acceptance checks still required

Use a disposable test directory, not a personal library.

1. Run `npm run tauri -- dev`. Open the native picker and cancel via its button and window close action; confirm current results and any running scan remain intact. Select a synthetic directory and verify the parented modal picker closes correctly.
2. Scan a tree containing nested WAV, MP3, and OGG candidates, mixed-case extensions, unsupported files, and symlinks. Check list names/extensions/availability, progress, empty results, partial warnings, refresh, and directory switching. Ensure typing and window interaction remain responsive.
3. Test keyboard-only selection, scanning, and navigation through results. Check focus visibility, status announcements, long names, and light/dark themes.
4. Rename or remove the selected root externally using only the disposable fixture. A subsequent command must revoke access and require reselection. Restart the application and confirm no filesystem access is restored automatically.
5. Build with `npm run tauri -- build --debug --no-bundle` and run `src-tauri/target/debug/soundshelf`. Verify selection → scan → React results with bundled assets, no IPC permission/CSP errors, and no need for a Vite server. This is the remaining native end-to-end check; an executable build alone does not prove it.

Do not begin Milestone 2 until these results are recorded and any native integration issues are fixed.
